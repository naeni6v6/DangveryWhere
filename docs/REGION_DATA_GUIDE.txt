1. 현재 상태

상위 8개 지역, 총 593개 후보의 저장 데이터와 서버용 로더를 준비했다.
(2026-09-19 관광공사 반려동물 동반여행 API 168건을 강원 5개 지역에 합쳐 508 → 593 이 되었다.)
2026-09-19 부터 화면에 연결하는 범위를 강원도로 좁혔다. 공공데이터가 강원에 가장 두껍게 쌓여
있어, 여러 도를 얕게 펼치기보다 한 도를 제대로 담는 쪽을 골랐다.
- 화면에 연결된 곳: 강릉(DB) + 춘천·양양·홍천·평창(준비 데이터) = 516건
- 저장본만 남겨 둔 곳: 제주시·서귀포·태안·가평 (파일은 그대로 두었다. 5절 참고)
지역을 고르지 않으면 강릉까지 합친 '강원 전체'(지역코드 all, 516건)가 기본으로 보인다.
all 은 저장본이 따로 없는 가상 지역이라 regionCatalog 에서 status='mixed' 로 구분한다.

강원 밖 지역을 다시 열려면 src/lib/domain/region.ts 의 RegionId 와 regionCatalog 에 그 지역을
되돌리면 된다. 저장본(src/lib/server/data/regions/*.json)과 로더(regions.ts)는 손대지 않았다.
DB 적재는 여전히 하지 않는다. db:setup 은 강릉 스냅샷만 places 테이블에 넣는다.
실시간 외부 API를 호출하는 기능이 아니라 이미 수집한 JSON을 지역별로 읽는다.
이 파일은 Git에 보관되는 인수인계 문서다. 새 대화에서도 먼저 읽으면 이어서 작업할 수 있다.

3. 코드 위치와 사용법 (향후 작업하는 개발자/에이전트용)

- 지역 선택·변환 코드: src/lib/server/regionPlaces.ts, src/lib/domain/region.ts
- 지역 목록 및 상태: src/lib/server/data/regions/index.json
- 지역별 저장본: src/lib/server/data/regions/{지역코드}.json
- 서버용 로더·타입: src/lib/server/regions.ts
- 데이터 준비 스크립트: scripts/prepare-region-data.mjs
- 목록 확인: npm run data:regions
- 검증: npm test -- src/lib/server/regions.test.ts

SvelteKit 서버 코드에서만 사용:

  import { listPreparedRegions, loadPreparedRegion } from '$lib/server/regions';

  const regions = listPreparedRegions();
  const dataset = await loadPreparedRegion('chuncheon');
  const candidates = dataset.places;

화면에 쓸 Place 로 받으려면 원본 로더 대신 변환기를 쓴다:

  import { getRegionPlaces, listRegions } from '$lib/server/regionPlaces';

  const places = await getRegionPlaces('chuncheon');  // Place[]
  const everywhere = await getRegionPlaces('all');    // 강원 전체 348건 (양양 먼저)
  const regionList = listRegions();                   // 강원 전체 + 강릉 + 준비 4개

로더는 지역별로 지연 로딩하며 네트워크·DB 요청을 만들지 않는다.
loadPreparedRegion은 매번 독립 사본을 반환한다. 반환 데이터를 수정해도 원본은 변하지 않는다.
src/lib/server 모듈을 브라우저 컴포넌트에서 직접 import하지 않는다.
getPlaces()는 지금도 강릉 전용이다. 지역별 목록은 getRegionPlaces()가 담당한다.

4. 데이터 계약

데이터셋: schemaVersion=1, status=prepared, collectedAt, region, places.
후보: id, regionId, name, category, address, latitude, longitude, phone, hours,
      reviewStatus=unverified, sources[].
출처: provider, recordId, url, collectedAt, updatedAt, verifiedAt=null,
      policyText, sizeText, raw.

- sources[]에는 같은 장소의 출처별 원문을 함께 보존했다. raw는 제공받은 원래 필드다.
- 강원에는 시설·제공물품·운영시간·설명·이미지 URL도 raw에 보존했다.
- 문화정보원에는 추가요금·실내외 공간 여부·원문 제한사항 등을 raw에 보존했다.
- kcisa- 접두어의 recordId는 CSV에 고유 ID가 없어 이름·주소로 만든 내부 식별자다.
- region- 접두어의 id는 준비 데이터 후보 식별자이며 기존 DB id를 대체하지 않는다.
- phone/hours/category 등 후보 대표값은 조사 정규화본의 값이다. 강원·문화정보원 원문이
  다르면 sources[]를 비교해 표시 정책을 결정해야 한다. 대표값이 최신이라는 뜻은 아니다.
- category=culture는 박물관·미술관·문예회관이다. 기존 Place 모델에는 없는 분류다.
- food의 카페/식당 구분은 아직 활성 모델로 변환하지 않았다. 원본 분류·키워드를 확인해야 한다.

6. 실제 지역 연결 전에 필요한 작업 (대부분 반영 완료)

[완료] PreparedRegionalPlace는 현재 앱의 Place와 다르다. 명시적인 변환을 구현해야 한다.
       → regionPlaces.ts 의 toPlace(). 타입 단언을 쓰지 않는다.
[완료] 체중 원문이 비었으면 무제한으로 판정하지 않는다. '미만'과 '이하'도 구분한다.
       → parseSourceWeight() 와 Place.sourceWeightBound.
[완료] 장소(실내)=Y 또는 inOutFlag=IN은 반려견 실내 허용 근거로 바로 사용하지 않는다.
       원문에 실외만 허용이라고 적힌 사례가 실제로 있다. → 두 플래그를 읽지 않는다.
[완료] 출처 간 충돌을 보존하고, 수집일과 업체 정책 확인일을 구분한다.
[완료] 현재 places DB의 ID 제약 및 카테고리 제약을 확인한다. 준비 데이터 JSON을
       db:setup에 그대로 넣거나 타입 단언으로 Place로 바꾸지 않는다.
       → places 테이블은 건드리지 않았다. 찜만 담을 수 있게 favorites.place_id 제약을
         db/005_region_favorites.sql 에서 넓혔다(외래키 없음).
[완료] 지역별 지도 중심/목록 필터를 구현하되 기존 강릉과 계정별 찜 데이터는 유지한다.
       → 찜 목록은 지금 보는 지역 밖의 장소도 favoritePlaces 로 함께 내려준다.
[남음] 업체에 규정을 다시 확인하는 일. 지금 준비 지역은 화면에서 '준비 데이터'로 표시되고
       모든 verifiedAt 은 null 이다. 확인을 마치기 전에는 이 표시를 떼지 않는다.
[남음] 강릉 30곳의 대표 메뉴. 강원 원본의 usedCost 칸에 들어 있는데, 강릉 스냅샷을 만들 때
       옮기지 않았다. scripts/import-gangneung.mjs 는 이제 그 칸을 옮기므로, 원본 스냅샷을
       다시 받아 스크립트를 돌리고 npm run db:setup 을 실행하면 채워진다.
       (아래 인증서 항목 때문에 원본 연결부터 확인해야 한다.)
[남음] 강원 원본 HTTPS 인증서 검증이 조사 시점에 실패했다. 이 저장 데이터 로더에는
       인증서 우회 코드가 없다. 미래 실시간 갱신은 원본 연결 상태부터 확인한다.

7. 한국관광공사 반려동물 동반여행 API (2026-09-19 합침)

승인키는 .env 의 DATA_GO_KR_SERVICE_KEY 에 둔다(서버 전용, PUBLIC_ 접두사 금지).
공공데이터포털 마이페이지 → 데이터활용 → Open API → 활용신청 상세의 '일반 인증키(Decoding)'.

  node --env-file=.env scripts/fetch-kto-pet-tour.mjs   # 강원 394건 원문 수집
  node scripts/merge-kto-pet-tour.mjs                   # 미리보기
  node scripts/merge-kto-pet-tour.mjs --write           # 저장
  npm run db:setup                                      # 강릉은 DB 가 원본이라 한 번 더

두 스크립트 모두 여러 번 돌려도 결과가 같다(같은 id 는 다시 만들지 않고, 같은 규정 문장은
다시 붙이지 않는다). 저장본은 src/lib/server/data/kto-pet-tour.json 이다.

조사하면서 확인한 함정 두 가지:
- areaCode=32(강원)로 조회하면 127건만 나온다. 레코드 상당수의 areacode 칸이 비어 있어서다.
  법정동 코드 lDongRegnCd=51 로 조회해야 394건이 다 나온다(전국 9,677건을 전량 받아
  주소로 걸러도 394건으로 같다).
- firstimage 가 비었다고 사진이 없는 게 아니다. 감자밭(contentid 2807380)은 firstimage 가
  빈 문자열인데 detailImage2 에는 3장이 있다. 사진 유무는 두 곳을 합쳐 판단한다.
- 엔드포인트는 KorPetTourService2 다. v1(KorPetTourService)은 폐기되어 400 이 떨어진다.

합친 결과:
- 이미 있던 장소 57곳에 출처를 덧붙였다(준비 데이터 30곳은 sources[] 에, 강릉 27곳은
  규정 문장에 '[한국관광공사]' 를 붙여서). 강릉은 DB 가 원본이라 sources[] 가 없다.
- 새 장소 168곳을 추가했다(강릉 83·춘천 63·평창 11·양양 9·홍천 2).
  관광공사 원본으로 만든 강릉 장소의 id 는 gw-k-<contentId> 다(db/007 이 허용).
- 사진 135곳에 새로, 51곳에 덧붙였다. 총 2,302장 중 우리 지역 몫이다.

사진을 내려받지 않는 이유:
  강원 394건 중 282건이 공공누리 제3유형(출처표시 + 변경금지)이다. pettravel 사진처럼
  webp 로 줄이면 변경금지에 걸려, tong.visitkorea.or.kr 원본 주소를 그대로 쓴다.
  화면에는 photoCredit()(region.ts)이 '사진: 한국관광공사' 한 줄을 붙인다.

동반 규정(detailPetTour2)은 강원 394건 전부 응답한다. 칸별 채움 정도는
acmpyTypeCd 393 / etcAcmpyInfo 191 / acmpyNeedMtr 174 / acmpyPsblCpam 169 /
relaAcdntRiskMtr 105 / relaPosesFclty 61 건이다.
관광공사가 관리하는 자료지만 업체에 직접 확인한 날은 아니라 verifiedAt 은 그대로 null 이다.

8. 저장본 재생성

  npm run data:regions:prepare -- <조사 JSON 폴더>

입력 파일:
- normalized-candidate-places.json
- pettravel-all-details.json
- culture-travel-allowed.json

처음 사용한 로컬 조사 폴더:
  C:/DangveryWhere/research/pet-region-20260917

입력 폴더는 초기 준비를 재실행할 때만 필요하다. 체크인된 8개 JSON을 읽는 로더와
목록 확인 명령은 이 외부 폴더 없이 작동한다.
준비 스크립트는 네트워크·DB를 사용하지 않고 전체 입력 검증 후 저장본을 다시 만든다.
새 원본 수집과 지역 재정규화는 별도 갱신 작업이다.

9. 업소 홈페이지 대표 사진 (2026-09-19)

관광공사 API 를 합친 뒤에도 516곳 중 112곳(동물병원 제외)에 사진이 없었다. 대부분 개인이
운영하는 애견펜션·카페라 관광공사 자료에 없고, 다른 공공 API 도 지금 키로는 호출이 안 된다
(아래 "조사 결과" 참고). 그래서 원본 데이터에 적힌 업소 홈페이지에서 대표 사진 한 장씩을
사람이 고르는 방식으로 채웠다.

  node scripts/fetch-homepage-photos.mjs           # 저장
  node scripts/fetch-homepage-photos.mjs --dry-run # 미리보기

- 목록은 src/lib/server/data/homepage-photos.json 이다. 자동 수집이 아니라 홈페이지를 하나씩
  열어 og:image 나 첫 화면 사진 줄에서 고른 것이며, 로고·배너·공지 이미지는 뺐다.
- 저장 위치는 static/places/homepage/<id>.webp (900px 표지). 업소 사이트는 http 전용 호스트가
  많아(인증서 만료·자체서명) https 배포에서 핫링크가 막혀, pettravel 사진처럼 받아 둔다.
  관광공사 visitkorea CDN 사진만 hotlink: true 로 두고 원본 주소를 그대로 건다.
- 화면에는 photoCredit()(region.ts)이 "사진: 업소 홈페이지" 를 붙인다. 이 줄이 있으면 정보
  출처 칸은 "정보·사진 출처" 대신 "정보 출처" 로 나온다(사진은 데이터 제공처 것이 아니라서).
- 업소 저작물이라 공공누리가 아니다. 출처 표기 + 업소 링크(홈페이지·네이버 지도)를 같이 두고,
  업소가 내려 달라고 하면 목록에서 빼고 스크립트를 다시 돌리면 된다.
- verifiedAt 은 그대로 null 이다. 사진이 있다고 규정을 확인한 건 아니다.

조사 결과(2026-09-19, 사진 없는 112곳 기준):
- 홈페이지 주소가 있는 곳 74 → 접속 52 → og:image 살아 있음 21 → 로고 아닌 실사진 15.
  여기에 첫 화면 사진 줄에서 고른 3곳(그랑샤리오·꼬로몽·작은 통나무집)을 더해 18곳.
  나머지 홈페이지는 DNS 실패·도메인 만료·준비중 페이지·인스타그램(로그인 없이는 og 없음)이다.
- 관광공사 국문 관광정보(KorService2, data.go.kr 15101578)·관광사진 정보(PhotoGalleryService1,
  15101914)·고캠핑(15101933)은 지금 키로 SERVICE_KEY_IS_NOT_REGISTERED_ERROR(403)다.
  세 건 모두 별도 활용신청이 필요하다(개발단계 자동승인). 커버리지는 승인 뒤에 재야 안다.
- 네이버·카카오 이미지 검색은 약관상 결과 저장·재배포가 금지라 쓰지 않는다
  (네이버 검색 API 약관 2.3, 카카오 개발자 운영정책 제5조 20·30호).

10. 상세 정보 확인 링크 (2026-09-19)

상세 화면의 [전화 문의]·[길찾기] 두 버튼을 [상세 정보 확인 ↗] 하나로 합쳤다. 전화번호는 주소
아래에 아이콘과 함께 tel: 링크로 보여 준다(웹 WebPlaceDetail, 모바일 PlaceDetail, 찜 목록).

  node scripts/build-place-links.mjs             # src/lib/data/placeLinks.json 다시 만들기
  node scripts/build-place-links.mjs --offline   # 접속 확인 없이 후보만

- 버튼이 여는 곳은 placeLink()(domain/placeLink.ts)가 정한다. placeLinks.json 에 업소 홈페이지가
  있으면 그곳, 없으면 네이버 지도 검색(naverPlaceUrl, "이름 + 시군구")이다. 그래서 링크가 아예
  안 뜨는 장소는 없다.
- 홈페이지 후보는 지역 저장본의 homePage·홈페이지 칸, 관광공사 저장본의 common.homepage, 강릉
  gw-<번호> 장소는 강원 원본 API(detailSeqPart.do)의 homePage 에서 모은다. 접속되는 것만 남긴다
  (DNS 실패·타임아웃·404·주차 페이지 제외. 403/418 봇 차단과 인증서 오류는 브라우저에서 열리므로
  남김). 같은 주소에 같은 가게가 출처별로 둘 들어온 경우("서프쉑"/"서프쉑 카페")는 한쪽 주소를
  나눠 쓴다.
- 목록은 업소 링크가 있는 장소를 먼저 보여 준다(directLinkFirst, 웹 /web/explore 와 모바일 첫
  화면). 모든 장소에 업소 페이지를 달 수 없어서 달린 곳이 앞에 오게 해 달라는 요청이다.
- 네이버 업소 페이지(map.naver.com/p/entry/place/<id>)로 바로 가려면 장소 ID 가 필요한데 원본
  어디에도 없고, 네이버 지도 검색은 자동 조회를 캡차로 막는다. ID 를 손으로 모으는 칸을 두면
  placeLinks.json 과 같은 방식으로 붙일 수 있다.
