작성·수집 기준: 2026-09-17
연결 기준: 2026-09-19 (다루는 범위를 강원도로 좁힘)

1. 현재 상태

상위 8개 지역, 총 508개 후보의 저장 데이터와 서버용 로더를 준비했다.
2026-09-19 부터 화면에 연결하는 범위를 강원도로 좁혔다. 공공데이터가 강원에 가장 두껍게 쌓여
있어, 여러 도를 얕게 펼치기보다 한 도를 제대로 담는 쪽을 골랐다.
- 화면에 연결된 곳: 강릉(DB) + 춘천·양양·홍천·평창(준비 데이터) = 348건
- 저장본만 남겨 둔 곳: 제주시·서귀포·태안·가평 (파일은 그대로 두었다. 5절 참고)
지역을 고르지 않으면 강릉까지 합친 '강원 전체'(지역코드 all, 348건)가 기본으로 보인다.
all 은 저장본이 따로 없는 가상 지역이라 regionCatalog 에서 status='mixed' 로 구분한다.

강원 밖 지역을 다시 열려면 src/lib/domain/region.ts 의 RegionId 와 regionCatalog 에 그 지역을
되돌리면 된다. 저장본(src/lib/server/data/regions/*.json)과 로더(regions.ts)는 손대지 않았다.
DB 적재는 여전히 하지 않는다. db:setup 은 강릉 스냅샷만 places 테이블에 넣는다.
실시간 외부 API를 호출하는 기능이 아니라 이미 수집한 JSON을 지역별로 읽는다.
이 파일은 Git에 보관되는 인수인계 문서다. 새 대화에서도 먼저 읽으면 이어서 작업할 수 있다.

연결된 곳:
- 지역 선택 UI: src/lib/components/web/RegionPicker.svelte (헤더·랜딩 상단, 첫 항목이 강원 전체)
  차례는 강원 전체 → 구분선 → 시도 묶음(지금은 강원 하나)이고, 지역은 북 → 남 순이다.
  순서는 regionCatalog 에 적어 둔 차례 그대로이며, 어긋나면 regionPlaces.test.ts 가 잡는다.
- 지역 선택 저장: src/lib/server/regionSelection.ts (?region= → 쿠키 dangverywhere-region)
- 준비 데이터 → Place 변환: src/lib/server/regionPlaces.ts
- 지도 중심·확대 단계·출처: src/lib/domain/region.ts (regionCatalog)
- 찜 목록의 지역 확장: db/005_region_favorites.sql, findPlacesByIds()
- 식당·카페 대표 메뉴: db/006_menu.sql, menuOf() (regionPlaces.ts), menuGroups() (place.ts)

변환하면서 지킨 것(6절 요구사항):
- 체중 원문이 비면 무제한으로 보지 않는다. '미만'과 '이하'는 sourceWeightBound 로 구분한다.
- 장소(실내) 여부 / inOutFlag 는 실내 동반 근거로 쓰지 않는다. 규정은 원문 문장만 옮긴다.
- 출처가 둘이면 '[강원 반려동반관광]' / '[한국문화정보원]' 을 붙여 양쪽을 모두 남긴다.
- category=culture 는 Place 에 '문화시설' 분류로 추가했다(강릉 데이터에는 없다).
- 수집일(importedAt)과 규정 확인일(verifiedAt=null)을 화면에서도 구분해 표시한다.

3. 코드 위치와 사용법 (향후 작업하는 개발자/에이전트용)

- 지역 선택·변환 코드: src/lib/server/regionPlaces.ts, src/lib/domain/region.ts
- 지역 목록 및 상태: src/lib/server/data/regions/index.json
- 지역별 저장본: src/lib/server/data/regions/{지역코드}.json
- 서버용 로더·타입: src/lib/server/regions.ts
- 데이터 준비 스크립트: scripts/prepare-region-data.mjs
- 목록 확인: npm run data:regions
- 검증: npm test -- src/lib/server/regions.test.ts

SvelteKit 서버 코드에서만 사용:

  import { listPreparedRegions, loadPreparedRegion } from '$lib/server/regions';

  const regions = listPreparedRegions();
  const dataset = await loadPreparedRegion('chuncheon');
  const candidates = dataset.places;

화면에 쓸 Place 로 받으려면 원본 로더 대신 변환기를 쓴다:

  import { getRegionPlaces, listRegions } from '$lib/server/regionPlaces';

  const places = await getRegionPlaces('chuncheon');  // Place[]
  const everywhere = await getRegionPlaces('all');    // 강원 전체 348건 (양양 먼저)
  const regionList = listRegions();                   // 강원 전체 + 강릉 + 준비 4개

로더는 지역별로 지연 로딩하며 네트워크·DB 요청을 만들지 않는다.
loadPreparedRegion은 매번 독립 사본을 반환한다. 반환 데이터를 수정해도 원본은 변하지 않는다.
src/lib/server 모듈을 브라우저 컴포넌트에서 직접 import하지 않는다.
getPlaces()는 지금도 강릉 전용이다. 지역별 목록은 getRegionPlaces()가 담당한다.

4. 데이터 계약

데이터셋: schemaVersion=1, status=prepared, collectedAt, region, places.
후보: id, regionId, name, category, address, latitude, longitude, phone, hours,
      reviewStatus=unverified, sources[].
출처: provider, recordId, url, collectedAt, updatedAt, verifiedAt=null,
      policyText, sizeText, raw.

- sources[]에는 같은 장소의 출처별 원문을 함께 보존했다. raw는 제공받은 원래 필드다.
- 강원에는 시설·제공물품·운영시간·설명·이미지 URL도 raw에 보존했다.
- 문화정보원에는 추가요금·실내외 공간 여부·원문 제한사항 등을 raw에 보존했다.
- kcisa- 접두어의 recordId는 CSV에 고유 ID가 없어 이름·주소로 만든 내부 식별자다.
- region- 접두어의 id는 준비 데이터 후보 식별자이며 기존 DB id를 대체하지 않는다.
- phone/hours/category 등 후보 대표값은 조사 정규화본의 값이다. 강원·문화정보원 원문이
  다르면 sources[]를 비교해 표시 정책을 결정해야 한다. 대표값이 최신이라는 뜻은 아니다.
- category=culture는 박물관·미술관·문예회관이다. 기존 Place 모델에는 없는 분류다.
- food의 카페/식당 구분은 아직 활성 모델로 변환하지 않았다. 원본 분류·키워드를 확인해야 한다.

5. 출처와 미수집 API

확보:
- 강원관광재단 반려동물 동반관광 API: https://www.pettravel.kr/petapi/api/way
- 한국문화정보원 공식 CSV: https://www.data.go.kr/data/15111389/fileData.do

아직 준비 데이터에 미포함:
- 관광공사 반려동물 전용 API: https://www.data.go.kr/data/15135102/openapi.do
- 고캠핑 API: https://www.data.go.kr/data/15101933/openapi.do

위 두 API는 현재 프로젝트에 승인키가 없어 전량 수집하지 않았다.
index.json의 providers 상태에도 미수집임을 명시했다.
관광공사 홈페이지에서 조회한 선별 목록은 조사 보조자료였으며 이 저장본에는 섞지 않았다.

문화정보원 작성일은 2022-11-30 또는 2025-03-24이며, 2026-09-17은 수집일이다.
강원 원본에는 규정 확인일이 없어 updatedAt=null로 남겼다.
이번 준비로 업체 정책을 새로 확인한 것은 아니므로 모든 verifiedAt은 null이다.

6. 실제 지역 연결 전에 필요한 작업 (대부분 반영 완료)

[완료] PreparedRegionalPlace는 현재 앱의 Place와 다르다. 명시적인 변환을 구현해야 한다.
       → regionPlaces.ts 의 toPlace(). 타입 단언을 쓰지 않는다.
[완료] 체중 원문이 비었으면 무제한으로 판정하지 않는다. '미만'과 '이하'도 구분한다.
       → parseSourceWeight() 와 Place.sourceWeightBound.
[완료] 장소(실내)=Y 또는 inOutFlag=IN은 반려견 실내 허용 근거로 바로 사용하지 않는다.
       원문에 실외만 허용이라고 적힌 사례가 실제로 있다. → 두 플래그를 읽지 않는다.
[완료] 출처 간 충돌을 보존하고, 수집일과 업체 정책 확인일을 구분한다.
[완료] 현재 places DB의 ID 제약 및 카테고리 제약을 확인한다. 준비 데이터 JSON을
       db:setup에 그대로 넣거나 타입 단언으로 Place로 바꾸지 않는다.
       → places 테이블은 건드리지 않았다. 찜만 담을 수 있게 favorites.place_id 제약을
         db/005_region_favorites.sql 에서 넓혔다(외래키 없음).
[완료] 지역별 지도 중심/목록 필터를 구현하되 기존 강릉과 계정별 찜 데이터는 유지한다.
       → 찜 목록은 지금 보는 지역 밖의 장소도 favoritePlaces 로 함께 내려준다.
[남음] 업체에 규정을 다시 확인하는 일. 지금 준비 지역은 화면에서 '준비 데이터'로 표시되고
       모든 verifiedAt 은 null 이다. 확인을 마치기 전에는 이 표시를 떼지 않는다.
[남음] 강릉 30곳의 대표 메뉴. 강원 원본의 usedCost 칸에 들어 있는데, 강릉 스냅샷을 만들 때
       옮기지 않았다. scripts/import-gangneung.mjs 는 이제 그 칸을 옮기므로, 원본 스냅샷을
       다시 받아 스크립트를 돌리고 npm run db:setup 을 실행하면 채워진다.
       (아래 인증서 항목 때문에 원본 연결부터 확인해야 한다.)
[남음] 강원 원본 HTTPS 인증서 검증이 조사 시점에 실패했다. 이 저장 데이터 로더에는
       인증서 우회 코드가 없다. 미래 실시간 갱신은 원본 연결 상태부터 확인한다.

7. 저장본 재생성

  npm run data:regions:prepare -- <조사 JSON 폴더>

입력 파일:
- normalized-candidate-places.json
- pettravel-all-details.json
- culture-travel-allowed.json
- analysis.json

처음 사용한 로컬 조사 폴더:
  C:/DangveryWhere/research/pet-region-20260917

입력 폴더는 초기 준비를 재실행할 때만 필요하다. 체크인된 8개 JSON을 읽는 로더와
목록 확인 명령은 이 외부 폴더 없이 작동한다.
준비 스크립트는 네트워크·DB를 사용하지 않고 전체 입력 검증 후 저장본을 다시 만든다.
새 원본 수집과 지역 재정규화는 별도 갱신 작업이다.
